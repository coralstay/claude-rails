# TASK-14: README 축약 + doc-2 분리

## 문제

README가 677줄까지 자라 있었다. 사용자 피드백: "리드미 너무 길어.. 이거 안읽어."

## 해결

README.md를 33줄로 줄이고(의도 문장, 왜 한 문단, 뭐가 있나 개요, 설치 명령, 포인터
5개만), 기존 0/2~12장 전체(운영-개인 레포 맥락, Phase 명세, HIL 표, 28개 훅 스펙, 설정
예시, 알려진 한계, 설치/삭제, 파일 구성)를 새로 만든 backlog doc `doc-2`("claude-rails
상세 레퍼런스")로 그대로 옮겼다 — 정보 손실 없이 그릇만 바꿨다.

## 왜 이 방법을 택했나

두 가지 옵션이 있었다: (a) 내용을 실제로 줄이기(요약/삭제), (b) 내용은 그대로 두고
보관 위치만 옮기기. (a)는 "누가 언제 이 상세 스펙이 필요해질지 모른다"는 점에서
정보 손실 위험이 있었고, 이미 backlog.md CLI로 doc를 만들 수 있는 인프라가 있었으므로
(b)를 택했다 — README는 첫인상/의도 전달용, doc-2는 레퍼런스용으로 역할을 나눴다.

## 결과

README.md 677→33줄. `doc-2` 신설(682줄, 기존 내용 그대로). 커밋: `25323af`(README),
`a6f17f0`(Done). 이후 TASK-16에서 훅 표가 다시 README로 일부 돌아왔고, TASK-17에서
생애주기 표로 확장됐다 — "얼마나 짧아야 하는가"는 고정된 답이 아니라 요청에 따라
계속 조정되는 값이라는 걸 이후 태스크들이 보여준다(decision-6 참고).
