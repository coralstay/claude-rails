# TASK-19: README 정중한 존댓말 재작성 + 훅 목록 파일 링크

## 문제

사용자 요청: "어투나 말투도, 경어로 쓰고 존대하는 말로 겸손한 말투로 아주 정중한
글로 써. 다시 적어. 그리고 훅 목록 2가지있는데, 실제 파일 링크도 걸어줘." TASK-18에서
이미 -습니다체로 바꿨지만, 사용자는 그보다 더 정중하고 겸손한 어투를 원했다. 또한
"훅 목록"이 README(생애주기 표)와 doc-2 8장(이벤트별 훅 스펙 표) 두 곳에 있는데,
어느 쪽에도 훅 이름이 실제 소스 파일로 연결돼 있지 않았다.

## 무엇을 했나

- README.md 전체를 "말씀드립니다", "소개해 드립니다", "안내해 드립니다", "~하였습니다"
  같은 정중한 어휘와 문장 구조로 다시 썼다. 단순 종결어미 치환을 넘어, 각 섹션
  헤더 자체도 "왜 필요했는지 말씀드립니다"처럼 정중한 문장형으로 바꿨다.
- README의 생애주기 표(41행)와 doc-2 8장의 이벤트별 훅 스펙 표(41행) — 두 "훅 목록"
  모두에서 훅 이름을 실제 `hooks/*.py` 파일로 연결되는 마크다운 링크로 바꿨다. doc-2는
  `backlog/docs/reference/`에 있으므로 `../../../hooks/<이름>.py` 상대경로를 사용했다.

## 왜 이 방법을 택했나

정중함의 정도를 사람이 판단하기는 어려워서, "정중한 표현으로 알려진 패턴(말씀드립니다,
~해 드립니다, 겸양 표현)"을 최대한 일관되게 적용하는 쪽을 택했다 — 문장마다 다르게
튀지 않도록 통일성을 우선했다.

링크는 손으로 41개씩 두 번 넣으면 오타가 나기 쉬워서, Python 스크립트로 테이블 첫
컬럼의 `` `hookname.py` `` 패턴을 찾아 일괄 치환했다. 치환 후 모든 링크가 실제
존재하는 파일을 가리키는지 스크립트로 재검증했다.

## 결과

README.md, doc-2 모두 수정. 링크 41+41개 전부 유효한 파일 확인. 전체 테스트 438
passed(코드 변경 없음). 커밋: `6eadb91`(수정).
